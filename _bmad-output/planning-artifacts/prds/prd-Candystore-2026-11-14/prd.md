# Product requirements correction: daily turns from the current project

## Purpose and status

This scoped PRD sets the **proposed** user-facing contract for `cs today`; it is not a claim that the command exists. It corrects the agent-surface direction in the [2026-09-04 live-feed plan](../../../candystore-live-feed-plan.md) without rewriting that historical plan or expanding the current implementation ticket. The primary consumer is an agent (and its human operator) asking what happened today in the project it is working on. The relevant alternative is the current low-level event feed or a bounded session handoff; neither answers that question in one step.

**Current checkout, 2026-11-14, `620d2b1`:** `pyproject.toml` exposes the `candystore` console script; `candystore/cli.py` supports `serve` and `context latest`, but no `cs` alias or `today` command. `context latest` resolves cwd through the main checkout while retaining submodule identity, then uses the project registry. It defaults to three recent sessions in 30 days, excludes the current session when known, and samples up to 60 narrative and 120 tool events per session (`candystore/context.py`, `docs/context-handoff.md`). The event feed already has a Turns lens (`docs/audits/2026-11-11-content-retention.md`); a lens over events is not yet a complete daily turn list. Nothing here is implemented by this document.

## Proposed contract and vocabulary

- **Project**: the single registered PJangler project resolved from the caller's cwd. The default path is the current directory, including nested directories and worktrees via the existing project-resolution behavior; a submodule remains its own project. A directory with no unambiguous registered project is not guessed from its basename. Explicit project selection may be offered as a correction path, but is never required for a registered cwd.
- **Turn**: one **observed top-level conversation turn start** attributable to that Project, identified by its recorded turn-start event and source session/CLI; optional recorded completion supplies the answer. A session can have many turns. An invocation, hook receipt, tool request/completion, annotation or task event is not a turn. Preserve distinct turns even when one session contains several. Do not collapse them into one session summary or expand a turn into all its tools.
- **Today**: the caller's current local calendar date in its detected IANA time zone. Freeze date, zone and an **as-of instant** at command start; use the interval **[local midnight, next local midnight)** translated to instants and include recorded starts through the as-of instant (not future-dated starts). Display that as-of instant so “all” has an honest cutoff; a subsequent invocation may find late-arriving evidence. DST days can be 23 or 25 hours. If the local zone cannot be established reliably, use **UTC**, announce the fallback, and show the actual zone and bounds in the response. A turn belongs to the day of its recorded start, even when its reply arrives the next day. A turn started before midnight is not a new turn today merely because it completed today. This is a reversible product choice, not current service behavior.
- **Observed coverage**: every matching recorded turn start within the selected day and Project, **including the caller's current session**, not every turn that might have happened but was never captured by a producer. Show start-only turns as unfinished/answer-not-recorded, not as failures or fabricated completions. If no start was recorded, do not turn an orphan completion into a made-up request; report orphan/uncertain coverage separately when detected. Missing prompt text on a start is `request not captured`, not a guessed request from adjacent tools. Exact tool-to-turn linkage is not generally present (`docs/audits/2026-11-11-content-retention.md`, §2); do not assert it from timestamp proximity. If a completion has no reliable turn identity, leave it unpaired and disclose the uncertainty rather than attach it to the nearest start.

**Decision record.** Compared with a rolling 24-hour window, a local calendar day matches “today”; `it-behaves-like-it-looks` wins. Compared with silently presuming UTC or guessing a zone, explicitly labeled UTC fallback is reversible and auditable (`reversible-beats-cautious`). Compared with sampling sessions or inventing turn links to fill gaps, listing recorded starts with coverage warnings preserves the platform's evidence (`it-behaves-like-it-looks`; Momo #2 **Dogfood the Platform** and #3 **Build LEGO, Not Statues / Rule of Three**). The chosen seam is the existing CLI, project registry and query service, not a new query stack.

## The single task-oriented feature

**FR-1 — Default daily view.** From a registered project directory, `cs today` displays that project's recorded turns for the frozen local calendar day without mandatory project, date-range, event-type, lens, or raw-query arguments. The first line identifies the project, date, time zone and local interval. This is the intended high-level interface, not an implementation of a natural-language query engine. A stable alternative name may be chosen during CLI implementation, but the requested `cs today` experience and example must work (an alias or equivalent packaging is an implementation decision).

**FR-2 — Legible turn evidence.** Each row carries start time (with zone), CLI, source session identifier, turn-start event ID, and recorded request excerpt or an explicit missing-request marker. Show recorded reply excerpt and its source event ID only when reliably paired; otherwise label answer status (`not recorded`, `in progress`, or `pairing uncertain` as evidence supports). Clearly distinguish an excerpt/truncation from missing content and provide a route to the stored source evidence. Do not promise that every producer captures request or reply text. Redact credential-shaped content in presentation without rewriting raw evidence, consistent with the current handoff.

**FR-3 — Order and full traversal.** Order turns by recorded start time ascending, then turn-start event ID for equal timestamps; preserve that order across pages. The default invocation must be able to reach **every** matching observed turn for the frozen day and Project, including across pages, with a terminal total or explicit completion indication. Either stream bounded pages to completion or expose a clear continuation that traverses a stable snapshot; a hidden limit, last-three-session cut, or sample presented as “all” fails. If a full traversal cannot finish, report incomplete coverage and a usable continuation/retry position; do not display a smaller list as if it were complete. Display a stated storage/retention boundary if it affects this day. This is a product guarantee to verify in CANDYS-60, not a claim that current `/events` or `/context/latest` already provides it.

**FR-4 — Empty and failure states.** Zero observed starts is `No recorded turns for <project> on <date> (<zone>)` with an explicit caveat that missing producer capture is not proof no work happened; exit successfully only when retrieval completed. An unresolved or ambiguous cwd yields a distinct actionable error (register the project or explicitly select one), never a cross-project fallback. Service outage, timeout, malformed response or partial retrieval yields nonzero exit and a retrieval-error message (including whether any pages were shown), not an empty-day result. Do not claim definitive completeness when source coverage or retention is unknown.

### Walkthroughs and verifiable scenarios

The following are **illustrative acceptance fixtures**, not captured CandyStore events or output from a working `cs today` command. Fix the clock and zone for each test so a runner can compare results without depending on its machine's current day.

1. **Populated day, including an open turn.** In `/home/delorenj/code/33GOD/candystore/web` with a registered `candystore` project, set local zone `America/New_York` and clock to **2026-11-14 15:00 EST**. Run `cs today`. Expect project `candystore`, date `2026-11-14`, interval `[2026-11-14 00:00 EST, 2026-11-15 00:00 EST)`, and **all fixture turn-start records** in that interval in ascending start-time/ID order. For fixtures with one 09:00 turn and its reliably linked 09:10 reply, show one turn with request and reply excerpts and distinct source IDs; for a second 11:00 start with no reply, show `not recorded`/`in progress` as supported. A fixture with 200 tool events inside the first turn still yields **two turns**, not 202. A fixture start at 23:58 with a reliably linked completion at 00:02 the next day belongs to Nov 14 when the same scenario is rerun after midnight; a Nov 13 23:58 start completed after midnight does not. Include an active caller session's start if recorded; do not silently exclude it. With more than one page of starts, follow continuation to the terminal result and assert every fixture start ID appears exactly once.
2. **Empty recorded day.** Same resolved cwd/day with no recorded turn starts and successful complete retrieval: display `No recorded turns for candystore on 2026-11-14 (America/New_York)` plus the capture caveat, exit 0; do not fill with the last three sessions or non-turn events. If an orphan completion is known, disclose it separately rather than manufacture a turn.
3. **Unresolved cwd.** From an unregistered directory, `cs today` reports that no single registered project could be resolved and offers registration or explicit project selection. Exit nonzero; do not silently list all projects or the closest directory basename.
4. **Retrieval failure.** For the registered cwd, force timeout or failure on page two after a successful page one. Exit nonzero, distinguish `incomplete retrieval` from `no recorded turns`, and preserve a retry/continuation path. Never announce a complete list of just page one.

A test of the DST transition (e.g. `America/New_York` on 2026-11-01) must use adjacent local midnights, not `start + 24h`. A recorded start with no prompt, a start without a reliable completion identity, and a producer with no turn-start capture must retain their explicit coverage states; these are not test-fixture gaps to paper over.

## Relationships and scope correction

- **CANDYS-59 / E13:** The agent surface is the home of this task-oriented entry point. The plan's E13 “follow-on” status and old ticket table are historical, not a fresh status report. High-level tasks become the front door for agents; structured filters and raw event inspection remain available when needed.
- **CANDYS-60 (CLI implementation):** Its older “`candystore/cli.py` (new)” and “second console script” premises are stale: both the module and `candystore` entry point already exist. Its proposed `projects`, `feed`, `session`, `recap` verbs are not implemented by this correction, nor does this document certify those verbs or ask this ticket to change CANDYS-60. The eventual CLI owner reconciles this proposed `cs today` contract with that implementation scope and uses existing project resolution and service queries instead of a parallel event-query engine.
- **CANDYS-61 (agent skill):** The eventual skill should teach the verified high-level daily command, its coverage caveats and source drill-down once the CLI is actually implemented. Its older empty-skills/no-agent-discovery premise is not fresh evidence of current packaging. No skill is authored here and no unimplemented command is advertised as working.
- **CANDYS-70 (UI text search):** This is a separate UI/event-search issue. Its documented gap includes reply text absent from the search index; do not claim that `q` finds every displayed field or use search as the turn-completeness mechanism. This correction neither duplicates the search bar nor schedules its fix.
- **Existing `context latest`:** Retain it as a 30-day, three-session default handoff (with sampled narrative/tool evidence and current-session exclusion). `today` is a calendar-day, turn-granularity listing including the current session, with no silent sample. Neither command substitutes for the other.

**Non-goals for CANDYS-71:** application/API/CLI or skill implementation, deployment, UI redesign, new dependency, query language, additional command catalogue, producer/linkage repair, retention infrastructure, and edits to neighboring tickets. In particular, **observed completeness is not historical capture completeness**. Use source IDs and explicit gaps instead of promising reconstruction the event trail cannot support.
